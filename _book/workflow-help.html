8  Flux de travail : obtenir de l’aide

Ce livre n’existe pas de manière isolée ; aucune ressource seule ne vous permettra de maîtriser R. Dès que vous commencerez à appliquer les techniques décrites dans ce livre à vos propres données, vous vous poserez des questions auxquelles nous ne répondons pas. Cette section décrit quelques conseils sur la manière d’obtenir de l’aide et de continuer à apprendre.

8.1 Google est votre allié

Si vous êtes bloqué, commencez par Google. Ajouter généralement « R » à votre recherche suffit pour la limiter à des résultats pertinents : si la recherche n’est pas utile, c’est souvent parce qu’il n’y a pas de résultats spécifiques à R disponibles. Aussi, ajouter des noms de packages comme « tidyverse » ou « ggplot2 » vous aidera à affiner les résultats pour que le code vous soit plus familier, par exemple, « how to make a boxplot in R » versus « how to make a boxplot in R with ggplot2 ». Google est particulièrement utile pour les messages d’erreur. Si vous recevez un message d’erreur et que vous n’avez aucune idée de ce qu’il signifie, essayez de le chercher sur Google ! Il y a de fortes chances que quelqu’un d’autre ait déjà été confronté à ce problème, et il y aura de l’aide quelque part sur le web. (Si le message d’erreur n’est pas en anglais, exécutez Sys.setenv(LANGUAGE = "en") et relancez le code ; vous avez plus de chances de trouver de l’aide à partir des messages d’erreur en anglais.)

Si Google ne vous aide pas, essayez Stack Overflow. Commencez par passer un peu de temps à chercher une réponse existante, en incluant [R], pour limiter votre recherche aux questions et réponses qui utilisent R.

8.2 Créer un reprex

Si votre recherche sur Google n’a rien donné, il est vivement recommandé de préparer un reprex, abréviation d’exemple reproductible minimal. Un bon reprex facilite la tâche aux personnes qui vout aideront, et souvent vous résolverez le problème vous-même au cours de sa création. Il y a deux étapes dans la création d’un reprex :

  • D’abord, vous devez rendre votre code reproductible. Cela signifie que vous devez capturer tout, c’est-à-dire inclure tous les appels library() et créer tous les objets nécessaires. Le moyen le plus simple de vous assurer que vous l’avez fait est d’utiliser le package reprex.

  • Dans un second temps, vous devez le simplifier (minimal). Supprimez tout ce qui n’est pas directement lié à votre problème. Cela implique généralement de créer un objet R beaucoup plus petit et plus simple que celui auquel vous êtes confronté dans la réalité, ou même d’utiliser des données intégrées.

Ça paraît long ! Et ça peut l’être, mais le jeu en vaut la chandelle :

  • 80 % du temps, créer un excellent reprex révèle la source de votre problème. C’est incroyable de voir combien de fois le processus de rédaction d’un exemple autonome et minimal vous permet de répondre à votre propre question.

  • Les 20 % restants du temps, vous aurez su cerner l’essence même de votre problème d’une manière qui permettra aux autres de s’en servir facilement. Cela améliore considérablement vos chances d’obtenir de l’aide !

Quand vous créez un reprex manuellement, vous pouvez oublier accidentellement quelque chose, ce qui signifie que votre code ne pourra pas être exécuté par quelqu’un d’autre. Évitez ce problème en utilisant le package reprex, contenu dans le tidyverse. Copiez le code suivant (ou sélectionnez-le sur RStudio Server ou Cloud) :

y <- 1:4
mean(y)

Exécutez ensuite reprex(), dont la sortie par défaut est formatée pour GitHub :

reprex::reprex()

Un aperçu HTML mis en page s’affichera dans le viewer de RStudio (si vous êtes sur RStudio) ou dans votre navigateur par défaut sinon. Le reprex est automatiquement copié dans votre presse-papiers (sur RStudio Server ou Cloud, vous devrez le copier vous-même) :

``` r
y <- 1:4
mean(y)
#> [1] 2.5
```

Ce texte est formaté d’une manière particulière, appelée Markdown, qui peut être collée sur des sites comme Stack Overflow ou GitHub qui le mettront automatiquement en page pour qu’il ressemble à du code. Voici à quoi ressemblerait ce Markdown une fois mis en page sur GitHub :

y <- 1:4
mean(y)
#> [1] 2.5

N’importe qui d’autre peut copier, coller et exécuter ce code immédiatement.

Il y a trois choses que vous devez inclure pour rendre votre exemple reproductible : les packages requis, les données et le code.

  1. Les packages doivent être chargés en haut du script pour qu’il soit facile de voir lesquels sont nécessaires. C’est le bon moment pour vérifier que vous utilisez la version la plus récente de chaque package ; vous avez peut-être découvert un bug qui a été corrigé depuis que vous avez installé ou mis à jour le package. Pour les packages du tidyverse, le moyen le plus simple de vérifier est d’exécuter tidyverse_update().

  2. Le moyen le plus simple d’inclure les données est d’utiliser dput() pour générer le code R nécessaire pour les recréer. Par exemple, pour recréer le jeu de données mtcars dans R, procédez comme suit :

    1. Exécutez dput(mtcars) dans R
    2. Copiez la sortie
    3. Dans reprex, tapez mtcars <-, puis collez.

    Essayez d’utiliser le plus petit sous-ensemble de vos données qui révèle toujours le problème.

  3. Prenez un peu de temps pour vous assurer que votre code est facile à lire pour les autres :

    • Assurez-vous que vous avez utilisé des espaces et que vos noms de variables sont concis mais informatifs.

    • Utilisez des commentaires pour indiquer où se situe votre problème.

    • Faites de votre mieux pour supprimer tout ce qui n’est pas lié au problème.

    Plus votre code est court, plus il est facile à comprendre et plus il est facile à corriger.

Terminez la vérification que vous avez réellement créé un exemple reproductible en commençant une nouvelle session R et en copiant / collant votre script.

Il n’est pas facile de créer des reprex, et il vous faudra de la pratique pour apprendre à créer de bons et minimaux reprex. Cependant, apprendre à poser des questions qui incluent du code et investir du temps pour le rendre reproductible, continuera à payer au fur et à mesure que vous apprendrez et maîtriserez R.

8.3 Investir en vous-même

Vous devriez aussi passer du temps à vous préparer à résoudre les problèmes avant qu’ils ne se produisent. Investir un peu de temps pour apprendre R chaque jour portera ses fruits à long terme. Une bonne manière est de suivre ce que l’équipe du tidyverse fait sur le blog tidyverse. Pour rester au courant de l’actualité de la communauté R plus largement, nous vous recommandons de lire R Weekly : c’est une initiative communautaire qui rassemble chaque semaine les nouvelles les plus intéressantes de la communauté R.

8.4 Résumé

Ce chapitre conclut la partie « Vue d’ensemble » du livre. Vous avez vu les parties les plus importantes du processus de science de données : la visualisation, la transformation, le nettoyage et l’importation. Maintenant que vous avez une vision globale de l’ensemble du processus, nous commençerons à entrer plus dans les détails.

La partie suivante du livre, « Visualiser », approfondit la grammaire des graphiques et la création de visualisations de données avec ggplot2, elle montre comment utiliser les outils que vous avez découvert jusqu’à présent pour mener une analyse exploratoire des données, et introduit les bonnes pratiques pour créer des graphiques à des fins de communication.
