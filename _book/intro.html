Introduction

La science de données est une discipline passionnante qui vous permet de transformer des données brutes en compréhension, perspectives et connaissances. L’objectif de « R pour la Science de Données » est de vous aider à apprendre les outils les plus importants de R pour faire de la science de données efficacement et de manière reproductible, tout en vous amusant 😃. À la fin de ce livre, vous disposerez des outils nécessaires pour relever une grande variété de défis en science de données en tirant le meilleur parti de R.

Ce que vous allez apprendre

La science de données est un vaste domaine, et il n’est pas possible d’en maîtriser la totalité en lisant un seul livre. Ce livre vise à vous donner des bases solides dans les outils les plus importants et suffisamment de connaissances pour trouver des ressources permettant d’aller plus loin si nécessaire. Notre modèle des étapes d’un projet de science de données typique ressemble à celui présenté en Figure 1.

Tout d’abord, vous devez importer vos données dans R. Cela signifie généralement que vous prenez des données stockées dans un fichier, une base de données ou une interface de programmation d’application (API) web, et que vous les chargez dans un data frame dans R. Si vous ne pouvez pas importer vos données dans R, vous ne pourrez pas faire de science de données !

Une fois vos données importées, il est conseillé de les nettoyer (rendre propres/tidy). Nettoyer vos données signifie les stocker dans une forme cohérente qui correspond à la sémantique du jeu de données avec la manière dont il est stocké. En bref, lorsque vos données sont propres, chaque colonne est une variable et chaque ligne est une observation. Les données propres sont importantes parce que leur structure cohérente vous permet de concentrer vos efforts sur la réponse aux questions relatives aux données, plutôt que de vous battre pour les mettre dans la bonne forme pour différentes fonctions.

Une fois que vous disposez de données propres, la prochaine étape habituelle est de les transformer. La transformation implique de restreindre aux observations d’intérêt (comme toutes les personnes dans une ville ou toutes les données de l’année dernière), créer de nouvelles variables qui sont des fonctions de variables existantes (comme le calcul de la vitesse à partir de la distance et du temps), et calculer un ensemble de statistiques résumées (comme des effectifs ou des moyennes). Le nettoyage et la transformation sont ensemble appelés manipulation de données, car mettre vos données dans une forme prête à utiliser ressemble souvent à un combat !

Une fois que vous disposez de données propres avec les variables dont vous avez besoin, il existe deux principaux moteurs de génération de connaissances : la visualisation et la modélisation. Ces deux approches ont des forces et des faiblesses complémentaires, de sorte que toute analyse de données réelle alternera plusieurs fois entre les deux.

La visualisation est une activité fondamentalement humaine. Une bonne visualisation vous montrera des choses que vous n’attendiez pas ou soulèvera de nouvelles questions sur les données. Une bonne visualisation peut aussi suggérer que vous posez la mauvaise question ou que vous devez collecter des données différentes. Les visualisations peuvent vous surprendre, mais elles ne passent pas particulièrement bien à l’échelle car elles nécessitent un être humain pour les interpréter.

Les modèles sont des outils complémentaires à la visualisation. Une fois que vos questions sont suffisamment précises, vous pouvez utiliser un modèle pour y répondre. Les modèles sont fondamentalement des outils mathématiques ou computationnels, ils passent donc généralement bien à l’échelle. Même quand ce n’est pas le cas, il est généralement moins coûteux d’acheter plus d’ordinateurs que d’acheter plus de cerveaux ! Mais tout modèle repose sur des hypothèses, et par nature, un modèle ne peut pas remettre en question ses propres hypothèses. Cela signifie qu’un modèle ne peut pas fondamentalement vous surprendre.

La dernière étape de la science de données est la communication, une partie absolument essentielle de tout projet d’analyse de données. Peu importe à quel point vos modèles et vos visualisations vous ont aidé à comprendre les données si vous ne pouvez pas aussi communiquer vos résultats à d’autres personnes.

Tous ces outils s’articulent grâce à la programmation. La programmation est un outil transversal que vous utilisez dans presque toutes les parties d’un projet de science de données. Vous n’avez pas besoin d’être un programmeur expert pour réussir en tant que data scientist, mais apprendre davantage la programmation est bénéfique car devenir un meilleur programmeur vous permet d’automatiser les tâches courantes et résoudre de nouveaux problèmes avec plus de facilité.

Vous utiliserez ces outils dans chaque projet de science de données, mais ils ne sont pas suffisants pour la plupart des projets. Il y a une règle approximative du 80/20 en jeu : vous pouvez traiter environ 80 % de chaque projet avec les outils que vous apprendrez dans ce livre, mais vous aurez besoin d’autres outils pour traiter les 20 % restants. Tout au long de ce livre, nous vous indiquerons des ressources pour en apprendre davantage.

Comment ce livre est organisé

La description précédente des outils de la science de données est organisée globalement selon l’ordre dans lequel vous les utilisez dans une analyse (même si, bien sûr, vous les parcourrez plusieurs fois de manière itérative). D’après notre expérience, cependant, commencer par l’importation et l’ordonnancement des données est sous-optimal, car 80 % du temps c’est routinier et ennuyeux, et les 20 % restants c’est étrange et frustrant. C’est un mauvais point de départ pour apprendre un nouveau sujet ! À la place, nous commencerons par la visualisation et la transformation de données déjà importées et propres. Ainsi, lorsque vous importerez et ordonnerez vos propres données, votre motivation restera élevée car vous saurez que la peine en vaut l’effort.

Dans chaque chapitre, nous essayons de suivre un schéma cohérent : commencer par quelques exemples motivants afin que vous puissiez voir la vue d’ensemble, puis plonger dans les détails. Chaque section du livre est accompagnée d’exercices pour vous aider à pratiquer ce que vous avez appris. Même s’il peut être tentant de sauter les exercices, il n’y a pas de meilleure façon d’apprendre qu’en pratiquant sur des problèmes réels.

Ce que vous n’apprendrez pas

Il existe plusieurs sujets importants que ce livre ne couvre pas. Nous pensons qu’il est important de rester résolument concentré sur l’essentiel pour vous permettre d’être opérationnel aussi rapidement que possible. Cela signifie que ce livre ne peut pas couvrir tous les sujets importants.

Modélisation

La modélisation est d’une importance capitale pour la science de données, mais c’est un vaste sujet et, malheureusement, nous n’avons pas la place ici de lui accorder le traitement qu’il mérite. Pour en savoir plus sur la modélisation, nous vous recommandons vivement Tidy Modeling with R de nos collègues Max Kuhn et Julia Silge. Ce livre vous enseignera la famille de packages tidymodels qui, comme vous pouvez le deviner d’après le nom, partage de nombreuses conventions avec les packages du tidyverse que nous utilisons dans ce livre.

Big data

Ce livre se concentre fièrement et principalement sur des jeux de données de petite taille, stockés en mémoire. C’est le bon point de départ, car vous ne pouvez pas vous attaquer au big data sans avoir de l’expérience avec les petites données. Les outils que vous apprendrez tout au long de la majeure partie de ce livre géreront facilement des centaines de mégaoctets de données et, avec un peu de soin, vous pouvez généralement les utiliser pour travailler avec quelques gigaoctets de données. Nous vous montrerons également comment extraire des données de bases de données et de fichiers parquet, qui sont souvent utilisés pour stocker des big data. Vous ne pourrez pas nécessairement travailler avec l’ensemble du jeu de données, mais ce n’est pas un problème car vous n’avez besoin que d’un sous-ensemble ou d’un échantillon pour répondre à la question qui vous intéresse.

Si vous travaillez régulièrement avec des données plus volumineuses (de 10 à 100 Go, par exemple), nous vous recommandons d’en apprendre davantage sur data.table. Nous ne l’enseignons pas ici car il utilise une interface différente de celle du tidyverse et nécessite d’apprendre des conventions différentes. Cependant, il est incroyablement rapide et le gain de performance vaut l’investissement en temps si vous travaillez avec de grandes données.

Python, Julia et d’autres langages

Dans ce livre, vous n’apprendrez rien sur Python, Julia ou tout autre langage de programmation utile pour la science de données. Ce n’est pas parce que nous pensons que ces outils sont mauvais. Ils ne le sont pas ! Et en pratique, la plupart des équipes de science de données utilisent un mélange de langages, souvent au moins R et Python. Mais nous croyons fermement qu’il est préférable de maîtriser un outil à la fois, et R est un excellent point de départ.

Prérequis

Nous avons fait quelques hypothèses sur ce que vous savez déjà pour tirer le meilleur parti de ce livre. Vous devriez être à l’aise avec les chiffres en général, et il est utile d’avoir déjà une certaine expérience de la programmation. Si vous n’avez jamais programmé, vous pourriez trouver que Hands on Programming with R de Garrett est un complément précieux à ce livre.

Vous avez besoin de quatre éléments pour exécuter le code de ce livre : R, RStudio, une collection de packages R appelée le tidyverse, et quelques autres packages. Les packages sont les unités fondamentales du code R reproductible. Ils comprennent des fonctions réutilisables, une documentation qui décrit comment les utiliser, et des données d’exemple.

R

Pour télécharger R, rendez-vous sur CRAN, le Comprehensive R Archive Network, https://cloud.r-project.org. Une nouvelle version majeure de R sort une fois par an, et il y a 2 à 3 versions mineures chaque année. Il est conseillé de le mettre à jour régulièrement. La mise à jour peut être un peu fastidieuse, surtout pour les versions majeures qui nécessitent de réinstaller tous vos packages, mais repousser cette tâche ne fait qu’aggraver les choses. Nous recommandons R 4.2.0 ou une version ultérieure pour ce livre.

RStudio

RStudio est un environnement de développement intégré, ou IDE, pour la programmation R, que vous pouvez télécharger depuis https://posit.co/download/rstudio-desktop/. RStudio est mis à jour plusieurs fois par an et vous préviendra automatiquement quand une nouvelle version est disponible, il n’est donc pas nécessaire de vérifier régulièrement. Il est conseillé de mettre à jour régulièrement pour profiter des dernières fonctionnalités. Pour ce livre, assurez-vous d’avoir au moins RStudio 2022.02.0.

Lorsque vous démarrez RStudio, comme le montre la Figure 2, vous verrez deux zones clés dans l’interface : le panneau de la console et le panneau de sortie. Pour l’instant, tout ce que vous devez savoir, c’est que vous saisissez le code R dans le panneau de la console et appuyez sur Entrée pour l’exécuter. Vous en apprendrez davantage au fil de la lecture !1

Le tidyverse

Vous devrez également installer quelques packages R. Un package R est une collection de fonctions, de données et de documentation qui étend les capacités de R base. L’utilisation de packages est essentielle pour utiliser R avec succès. La majorité des packages que vous apprendrez dans ce livre font partie du tidyverse. Tous les packages du tidyverse partagent une philosophie commune des données et de la programmation R, et sont conçus pour fonctionner ensemble.

Vous pouvez installer le tidyverse complet avec une seule ligne de code :

install.packages("tidyverse")

Sur votre ordinateur, saisissez cette ligne de code dans la console, puis appuyez sur Entrée pour l’exécuter. R téléchargera les packages depuis CRAN et les installera sur votre ordinateur.

Vous ne pourrez pas utiliser les fonctions, objets ou fichiers d’aide d’un package tant que vous ne l’aurez pas chargé avec library(). Une fois qu’un package est installé, vous pouvez le charger avec la fonction library() :

library(tidyverse)

#> ✔ forcats   1.0.1          ✔ stringr   1.6.0     
#> ✔ ggplot2   4.0.3          ✔ tibble    3.3.1     
#> ✔ lubridate 1.9.5          ✔ tidyr     1.3.2     
#> ✔ purrr     1.2.2          
#> ── Conflicts ─────────────────────────────────────── tidyverse_conflicts() ──

Cela vous indique que le tidyverse charge neuf packages : dplyr, forcats, ggplot2, lubridate, purrr, readr, stringr, tibble, tidyr. Ceux-ci sont considérés comme le cœur du tidyverse car vous les utiliserez dans presque toutes les analyses.

Les packages du tidyverse évoluent assez fréquemment. Vous pouvez voir si des mises à jour sont disponibles en exécutant tidyverse_update().

Autres packages

Il existe de nombreux autres excellents packages qui ne font pas partie du tidyverse, car ils résolvent des problèmes dans un domaine différent ou sont conçus selon un ensemble de principes sous-jacents différents. Cela ne les rend pas meilleurs ou moins bons ; cela les rend simplement différents. En d’autres termes, le complément du tidyverse n’est pas le « messyverse » mais de nombreux autres univers de packages interdépendants. À mesure que vous vous attaquerez à davantage de projets de science de données avec R, vous apprendrez de nouveaux packages et de nouvelles façons de penser les données.

Nous utiliserons de nombreux packages extérieurs au tidyverse dans ce livre. Par exemple, nous utiliserons les packages suivants car ils fournissent des jeux de données intéressants pour travailler lors de l’apprentissage de R :

install.packages(
  c("arrow", "babynames", "curl", "duckdb", "gapminder", 
    "ggrepel", "ggridges", "ggthemes", "hexbin", "janitor", "Lahman", 
    "leaflet", "maps", "nycflights13", "openxlsx", "palmerpenguins", 
    "repurrrsive", "tidymodels", "writexl")
  )

Nous utiliserons également une sélection d’autres packages pour des exemples ponctuels. Vous n’avez pas besoin de les installer maintenant ; souvenez-vous simplement que lorsque vous voyez une erreur de ce type :

library(ggrepel)
#> Error in library(ggrepel) : there is no package called 'ggrepel'

Vous devez exécuter install.packages("ggrepel") pour installer le package.

Exécuter du code R

La section précédente vous a montré plusieurs exemples d’exécution de code R. Le code dans le livre ressemble à ceci :

1 + 2
#> [1] 3

Si vous exécutez le même code dans votre console locale, cela ressemblera à ceci :

> 1 + 2
[1] 3

Il y a deux différences principales. Dans votre console, vous saisissez après le symbole >, appelé prompt ; nous n’affichons pas le prompt dans le livre. Dans le livre, la sortie est commentée avec #> ; dans votre console, elle apparaît directement après votre code. Ces deux différences signifient que si vous travaillez avec une version électronique du livre, vous pouvez facilement copier le code du livre et le coller dans la console.

Tout au long du livre, nous utilisons un ensemble cohérent de conventions pour désigner le code :

  • Les fonctions sont affichées dans une police spéciale pour le code et suivies de parenthèses, comme sum() ou mean().

  • Les autres objets R (comme les données ou les arguments de fonctions) sont dans une même police spéciale pour le code, sans parenthèses, comme flights ou x.

  • Parfois, pour indiquer clairement de quel package provient un objet, nous utiliserons le nom du package suivi de deux-points doubles, comme dplyr::mutate() ou nycflights13::flights. C’est également du code R valide.
