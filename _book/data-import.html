7  Importation de données

7.1 Introduction

Travailler avec les données fournies par les packages R est un excellent moyen de se familiariser avec les outils de science des données, mais à un moment donné, vous aurez envie de mettre en pratique ce que vous avez appris sur vos propres données. Ce chapitre vous montre les bases de l’import de fichiers de données dans R.

Nous nous concentrerons tout particulièrement sur l’import de fichiers tabulaires. Nous commencerons par des conseils pratiques pour gérer des caractéristiques comme les noms de colonnes, les types et les valeurs manquantes. Vous apprendrez ensuite à importer les données de plusieurs fichiers à la fois et à exporter des données de R dans un fichier. Enfin, vous verrez comment créer des data frames manuellement dans R.

7.1.1 Prérequis

Dans ce chapitre, vous découvrirez comment charger des fichiers classiques dans R avec le package readr, qui fait partie du tidyverse.

library(tidyverse)

7.2 Lire les données depuis un fichier

Pour commencer, nous nous concentrerons sur le type de fichier de données tabulaire le plus courant : le CSV (comma-separated values). Voici à quoi ressemble un fichier CSV simple. La première ligne, généralement appelée ligne d’en-tête, donne les noms des colonnes, et les six lignes suivantes contiennent les données. Les colonnes sont séparées, c’est-à-dire délimitées, par des virgules.

Student ID,Full Name,favourite.food,mealPlan,AGE
1,Sunil Huffmann,Strawberry yoghurt,Lunch only,4
2,Barclay Lynn,French fries,Lunch only,5
3,Jayendra Lyne,N/A,Breakfast and lunch,7
4,Leon Rossini,Anchovies,Lunch only,
5,Chidiegwu Dunkel,Pizza,Breakfast and lunch,five
6,Güvenç Attila,Ice cream,Lunch only,6

La Table 7.1 montre une représentation des mêmes données sous forme de tableau.

Nous pouvons importer ce fichier dans R en utilisant read_csv(). Le premier argument est le plus important : le chemin vers le fichier. Vous pouvez considérez le chemin comme l’adresse du fichier : le fichier s’appelle students.csv et il se trouve dans le dossier data.

students <- read_csv("data/students.csv")
#> Rows: 6 Columns: 5
#> ── Column specification ─────────────────────────────────────────────────────
#> Delimiter: ","
#> chr (4): Full Name, favourite.food, mealPlan, AGE
#> dbl (1): Student ID
#> 
#> ℹ Use `spec()` to retrieve the full column specification for this data.
#> ℹ Specify the column types or set `show_col_types = FALSE` to quiet this message.

Le code ci-dessus fonctionnera si votre fichier students.csv se trouve dans le dossier data de votre projet. Vous pouvez télécharger le fichier students.csv depuis https://pos.it/r4ds-students-csv ou l’importer directement à partir de cette URL avec :

students <- read_csv("https://pos.it/r4ds-students-csv")

Quand vous exécutez read_csv(), cela affiche un message indiquant le nombre de lignes et de colonnes des données, le séparateur utilisé, et les spécifications des colonnes (noms des colonnes organisés par type de données). Cela affiche également des informations sur la manière d’obtenir la spécification complète de la colonne et sur la façon de désactiver ce message. Ce message fait partie intégrante de readr, et nous en reparlerons en Section 7.3.

7.2.1 Conseils pratiques

Une fois que vous avez importé les données, la première étape consiste généralement à les transformer d’une manière ou d’une autre pour les rendre plus faciles à manipuler pour le reste de votre analyse. Jetons un nouveau coup d’œil aux données students en gardant cela à l’esprit.

students
#> # A tibble: 6 × 5
#>   `Student ID` `Full Name`      favourite.food     mealPlan            AGE  
#>          <dbl> <chr>            <chr>              <chr>               <chr>
#> 1            1 Sunil Huffmann   Strawberry yoghurt Lunch only          4    
#> 2            2 Barclay Lynn     French fries       Lunch only          5    
#> 3            3 Jayendra Lyne    N/A                Breakfast and lunch 7    
#> 4            4 Leon Rossini     Anchovies          Lunch only          <NA> 
#> 5            5 Chidiegwu Dunkel Pizza              Breakfast and lunch five 
#> 6            6 Güvenç Attila    Ice cream          Lunch only          6

Dans la colonne favourite.food, on trouve plusieurs aliments ainsi que la chaîne de caractères N/A qui devrait être un vrai NA que R reconnaît comme « not available ». Nous pouvons régler ce problème en utilisant l’argument na. Par défaut, la fonction read_csv() reconnaît uniquement les chaînes vides ("") comme valeurs manquantes NA, mais nous voulons qu’elle reconnaisse aussi la chaîne de caractères "N/A".

students <- read_csv("data/students.csv", na = c("N/A", ""))

students
#> # A tibble: 6 × 5
#>   `Student ID` `Full Name`      favourite.food     mealPlan            AGE  
#>          <dbl> <chr>            <chr>              <chr>               <chr>
#> 1            1 Sunil Huffmann   Strawberry yoghurt Lunch only          4    
#> 2            2 Barclay Lynn     French fries       Lunch only          5    
#> 3            3 Jayendra Lyne    <NA>               Breakfast and lunch 7    
#> 4            4 Leon Rossini     Anchovies          Lunch only          <NA> 
#> 5            5 Chidiegwu Dunkel Pizza              Breakfast and lunch five 
#> 6            6 Güvenç Attila    Ice cream          Lunch only          6

Vous remarquerez peut-être aussi que les colonnes Student ID et Full Name sont entourées de backticks. C’est parce qu’elles contiennent des espaces, ce qui enfreint les règles habituelles de R pour les noms de variables ; ce sont des noms non syntaxiques. Pour faire référence à ces variables, vous devez les entourer de backticks, ` :

students |> 
  rename(
    student_id = `Student ID`,
    full_name = `Full Name`
  )
#> # A tibble: 6 × 5
#>   student_id full_name        favourite.food     mealPlan            AGE  
#>        <dbl> <chr>            <chr>              <chr>               <chr>
#> 1          1 Sunil Huffmann   Strawberry yoghurt Lunch only          4    
#> 2          2 Barclay Lynn     French fries       Lunch only          5    
#> 3          3 Jayendra Lyne    <NA>               Breakfast and lunch 7    
#> 4          4 Leon Rossini     Anchovies          Lunch only          <NA> 
#> 5          5 Chidiegwu Dunkel Pizza              Breakfast and lunch five 
#> 6          6 Güvenç Attila    Ice cream          Lunch only          6

Une autre approche consiste à utiliser janitor::clean_names() qui applique quelques règles afin de les transformer toutes en snake_case en une seule opération1.

students |> janitor::clean_names()
#> # A tibble: 6 × 5
#>   student_id full_name        favourite_food     meal_plan           age  
#>        <dbl> <chr>            <chr>              <chr>               <chr>
#> 1          1 Sunil Huffmann   Strawberry yoghurt Lunch only          4    
#> 2          2 Barclay Lynn     French fries       Lunch only          5    
#> 3          3 Jayendra Lyne    <NA>               Breakfast and lunch 7    
#> 4          4 Leon Rossini     Anchovies          Lunch only          <NA> 
#> 5          5 Chidiegwu Dunkel Pizza              Breakfast and lunch five 
#> 6          6 Güvenç Attila    Ice cream          Lunch only          6

Une autre tâche courante après l’import des données est de vérifier les types de variables. Par exemple, meal_plan est une variable catégorielle avec un ensemble connu de valeurs possibles, qui en R devrait être présentée comme un facteur :

students |>
  janitor::clean_names() |>
  mutate(meal_plan = factor(meal_plan))
#> # A tibble: 6 × 5
#>   student_id full_name        favourite_food     meal_plan           age  
#>        <dbl> <chr>            <chr>              <fct>               <chr>
#> 1          1 Sunil Huffmann   Strawberry yoghurt Lunch only          4    
#> 2          2 Barclay Lynn     French fries       Lunch only          5    
#> 3          3 Jayendra Lyne    <NA>               Breakfast and lunch 7    
#> 4          4 Leon Rossini     Anchovies          Lunch only          <NA> 
#> 5          5 Chidiegwu Dunkel Pizza              Breakfast and lunch five 
#> 6          6 Güvenç Attila    Ice cream          Lunch only          6

Notez que les valeurs de la variable meal_plan sont restées identiques, mais le type de variable indiqué sous le nom de la variable a changé, passant de caractère (<chr>) à facteur (<fct>). Vous en apprendrez plus sur les facteurs dans le Chapitre 16.

Avant d’analyser ces données, vous devrez corriger la colonne age. Actuellement, age est une variable caractère parce que l’une des observations est écrite sous forme textuelle five au lieu du nombre 5. Nous discuterons des détails de la résolution de ce problème dans le Chapitre 20.

students <- students |>
  janitor::clean_names() |>
  mutate(
    meal_plan = factor(meal_plan),
    age = parse_number(if_else(age == "five", "5", age))
  )

students
#> # A tibble: 6 × 5
#>   student_id full_name        favourite_food     meal_plan             age
#>        <dbl> <chr>            <chr>              <fct>               <dbl>
#> 1          1 Sunil Huffmann   Strawberry yoghurt Lunch only              4
#> 2          2 Barclay Lynn     French fries       Lunch only              5
#> 3          3 Jayendra Lyne    <NA>               Breakfast and lunch     7
#> 4          4 Leon Rossini     Anchovies          Lunch only             NA
#> 5          5 Chidiegwu Dunkel Pizza              Breakfast and lunch     5
#> 6          6 Güvenç Attila    Ice cream          Lunch only              6

Une nouvelle fonction ici est if_else(), qui a trois arguments. Le premier argument test doit être un vecteur logique. Le résultat contiendra la valeur du deuxième argument, yes, quand test est TRUE, et la valeur du troisième argument, no, quand il est FALSE. Ici, nous disons que si age est la chaîne "five", nous la remplaçons par "5", sinon nous la laissons telle quelle. Vous en apprendrez plus sur if_else() et les vecteurs logiques dans le Chapitre 12.

7.2.2 Autres arguments

Il y a quelques autres arguments importants que nous devons mentionner, ils seront plus faciles à démontrer si nous vous montrons d’abord une astuce : read_csv() peut lire les chaînes de texte que vous avez créées et formatées comme un fichier CSV :

read_csv(
  "a,b,c
  1,2,3
  4,5,6"
)
#> Warning: The `file` argument of `read_csv()` should use `I()` for literal data as of
#> readr 2.2.0.
#>   
#>   # Bad (for example):
#>   read_csv("x,y\n1,2")
#>   
#>   # Good:
#>   read_csv(I("x,y\n1,2"))
#> # A tibble: 2 × 3
#>       a     b     c
#>   <dbl> <dbl> <dbl>
#> 1     1     2     3
#> 2     4     5     6

Généralement, read_csv() utilise la première ligne des données pour les noms de colonnes, c’est une convention très courante. Mais il arrive souvent que quelques lignes de métadonnées se trouvent au début du fichier. Vous pouvez utiliser skip = n pour ignorer les n premières lignes ou utiliser comment = "#" pour supprimer toutes les lignes commençant par (par exemple) # :

read_csv(
  "The first line of metadata
  The second line of metadata
  x,y,z
  1,2,3",
  skip = 2
)
#> # A tibble: 1 × 3
#>       x     y     z
#>   <dbl> <dbl> <dbl>
#> 1     1     2     3

read_csv(
  "# A comment I want to skip
  x,y,z
  1,2,3",
  comment = "#"
)
#> # A tibble: 1 × 3
#>       x     y     z
#>   <dbl> <dbl> <dbl>
#> 1     1     2     3

Dans d’autres cas, les données pourraient ne pas avoir de noms de colonnes. Vous pouvez utiliser col_names = FALSE pour dire à read_csv() de ne pas traiter la première ligne comme des en-têtes et de les étiqueter séquentiellement de X1 à Xn :

read_csv(
  "1,2,3
  4,5,6",
  col_names = FALSE
)
#> # A tibble: 2 × 3
#>      X1    X2    X3
#>   <dbl> <dbl> <dbl>
#> 1     1     2     3
#> 2     4     5     6

Autrement, vous pouvez passer à col_names un vecteur de caractères qui sera utilisé comme noms de colonnes :

read_csv(
  "1,2,3
  4,5,6",
  col_names = c("x", "y", "z")
)
#> # A tibble: 2 × 3
#>       x     y     z
#>   <dbl> <dbl> <dbl>
#> 1     1     2     3
#> 2     4     5     6

Ces arguments suffisent pour lire la plupart des fichiers CSV que vous rencontrerez dans la pratique. (Pour les autres, vous devrez examiner attentivement votre fichier .csv et consulter la documentation des nombreux autres arguments de read_csv().)

7.2.3 Autres types de fichiers

Une fois que vous maîtrisez read_csv(), l’utilisation des autres fonctions de readr est directe ; il est simplement question de savoir quelle fonction utiliser :

  • read_csv2() lit les fichiers séparés par des points-virgules. Ils utilisent ; au lieu de , pour séparer les champs et sont courants dans les pays qui utilisent , comme séparateur décimal.

  • read_tsv() lit les fichiers délimités par des tabulations.

  • read_delim() lit les fichiers avec n’importe quel séparateur, en essayant de deviner automatiquement le séparateur si vous ne le spécifiez pas.

  • read_fwf() lit les fichiers de largeur fixe. Vous pouvez spécifier les champs par leur largeur avec fwf_widths() ou par leur position avec fwf_positions().

  • read_table() lit une variante courante des fichiers de largeur fixe où les colonnes sont séparées par des espaces.

  • read_log() lit les fichiers journaux au format Apache.

7.3 Contrôler les types de colonnes

Un fichier CSV ne contient aucune information sur le type de chaque variable (c’est-à-dire si c’est un logique, un nombre, une chaîne de caractères, etc.), donc readr tentera de deviner le type. Cette section décrit comment ce processus fonctionne, comment résoudre certains problèmes courants qui le font échouer, et, si nécessaire, comment fournir vous-même les types de colonnes. Enfin, nous mentionnerons quelques stratégies générales utiles si readr échoue et que vous avez besoin d’avoir un meilleur aperçu de la structure de votre fichier.

7.3.1 Deviner les types

readr utilise une heuristique pour déterminer les types de colonnes. Pour chaque colonne, elle extrait les valeurs de 1 000 lignes2 espacées uniformément de la première à la dernière ligne, en ignorant les valeurs manquantes. Elle parcourt ensuite les questions suivantes :

  • Contient-elle uniquement F, T, FALSE ou TRUE (en ignorant la casse) ? Si oui, c’est un logique (logical).
  • Contient-elle uniquement des nombres (par exemple, 1, -4.5, 5e6, Inf) ? Si oui, c’est un nombre (number).
  • Correspond-elle à la norme ISO8601 ? Si oui, c’est une date ou une date/heure. (Nous reviendrons sur les dates/heures plus en détail dans la Section 17.2).
  • Sinon, ce doit être une chaîne de caractères (string).

Vous pouvez observer ce comportement en action dans cet exemple simple :

read_csv("
  logical,numeric,date,string
  TRUE,1,2021-01-15,abc
  false,4.5,2021-02-15,def
  T,Inf,2021-02-16,ghi
")
#> # A tibble: 3 × 4
#>   logical numeric date       string
#>   <lgl>     <dbl> <date>     <chr> 
#> 1 TRUE        1   2021-01-15 abc   
#> 2 FALSE       4.5 2021-02-15 def   
#> 3 TRUE      Inf   2021-02-16 ghi

Cette heuristique fonctionne bien si vous avez un jeu de données propre, mais en réalité, vous serez confrontés à de nombreux échecs.

7.3.2 Valeurs manquantes, types de colonnes et problèmes

La cause la plus fréquente d’échec de la détection des colonnes est la présence de valeurs inattendues dans une colonne, ce qui conduit à obtenir une colonne de type « caractère » au lieu d’un type plus spécifique. L’une des causes les plus courantes de ce problème est une valeur manquante enregistrée différemment de NA, que le package readr attend.

Prenez cet exemple simple de fichier CSV à 1 colonne :

simple_csv <- "
  x
  10
  .
  20
  30"

Si nous la lisons sans arguments supplémentaires, x devient une colonne caractère :

read_csv(simple_csv)
#> # A tibble: 4 × 1
#>   x    
#>   <chr>
#> 1 10   
#> 2 .    
#> 3 20   
#> 4 30

Dans ce très petit cas, vous pouvez facilement voir la valeur manquante .. Mais que se passe-t-il si vous avez des milliers de lignes avec seulement quelques valeurs manquantes représentées par des . disséminés parmi elles ? Une approche consiste à dire à readr que x est une colonne numérique, puis à voir où elle échoue. Vous pouvez faire cela avec l’argument col_types, qui prend une liste nommée où les noms correspondent aux noms de colonnes du fichier CSV :

df <- read_csv(
  simple_csv, 
  col_types = list(x = col_double())
)
#> Warning: One or more parsing issues, call `problems()` on your data frame for
#> details, e.g.:
#>   dat <- vroom(...)
#>   problems(dat)

Maintenant read_csv() signale qu’il y a eu un problème, et nous dit que nous pouvons en savoir plus avec problems() :

problems(df)
#> # A tibble: 1 × 5
#>     row   col expected actual file                                          
#>   <int> <int> <chr>    <chr>  <chr>                                         
#> 1     3     1 a double .      /tmp/Rtmp9BujpM/vroom-chr-to-file-1b3d853bbf5c

Cela nous indique qu’il y a eu un problème à la ligne 3, colonne 1, où readr attendait un double mais a trouvé un .. Cela suggère que ce jeu de données utilise . pour les valeurs manquantes. Nous fixons donc na = ".", la détection automatique réussit, nous donnant la colonne numérique que nous voulions :

read_csv(simple_csv, na = ".")
#> # A tibble: 4 × 1
#>       x
#>   <dbl>
#> 1    10
#> 2    NA
#> 3    20
#> 4    30

7.3.3 Types de colonnes

readr offre un total de neuf types de colonnes pour votre utilisation :

  • col_logical() et col_double() lisent les variables logiques et les nombres réels. Ces fonctions sont rarement nécessaires (sauf comme ci-dessus), car readr les devinera généralement automatiquement.
  • col_integer() lit les entiers. Nous faisons rarement la distinction entre entiers et doubles dans ce livre car ils sont fonctionnellement équivalents, mais lire explicitement les entiers peut parfois être utile car ils occupent la moitié de la mémoire des doubles.
  • col_character() lit les chaînes de caractères. C’est utile de les spécifier explicitement quand vous avez un identifiant numérique dans une colonne, c’est-à-dire une série de chiffres qui identifie un objet mais sur lequel il n’est pas pertinent d’appliquer des opérations mathématiques. Les exemples incluent les numéros de téléphone, les numéros de sécurité sociale, les numéros de carte de crédit, etc.
  • col_factor(), col_date() et col_datetime() créent respectivement des facteurs, des dates et des dates/heures ; vous en apprendrez plus sur ceux-ci quand nous arriverons à ces types de données en Chapitre 16 et Chapitre 17.
  • col_number() est un analyseur numérique permissif qui ignorera les composantes non numériques, et est particulièrement utile pour les devises. Vous en apprendrez plus dans le Chapitre 13.
  • col_skip() ignore une colonne afin qu’elle ne soit pas incluse dans le résultat, ce qui peut être utile pour accélérer la lecture des données si vous avez un gros fichier CSV et que vous ne voulez utiliser que certaines colonnes.

Il est aussi possible de remplacer l’heuristique par défaut qui devine les types en passant de list() à cols() et en spécifiant .default :

another_csv <- "
x,y,z
1,2,3"

read_csv(
  another_csv, 
  col_types = cols(.default = col_character())
)
#> # A tibble: 1 × 3
#>   x     y     z    
#>   <chr> <chr> <chr>
#> 1 1     2     3

Un autre paramètre utile est cols_only() qui ne lira que les colonnes que vous spécifiez :

read_csv(
  another_csv,
  col_types = cols_only(x = col_character())
)
#> # A tibble: 1 × 1
#>   x    
#>   <chr>
#> 1 1

7.4 Importer les données de plusieurs fichiers

Parfois, vos données sont réparties entre plusieurs fichiers au lieu d’être contenus en un seul. Par exemple, vous pourriez avoir les données de ventes de plusieurs mois, avec les données de chaque mois dans un fichier séparé : 01-sales.csv pour janvier, 02-sales.csv pour février, et 03-sales.csv pour mars. Avec read_csv(), vous pouvez lire ces données en une seule fois et les empiler les unes sur les autres dans un seul data frame.

sales_files <- c("data/01-sales.csv", "data/02-sales.csv", "data/03-sales.csv")
read_csv(sales_files, id = "file")
#> # A tibble: 19 × 6
#>   file              month    year brand  item     n
#>   <chr>             <chr>   <dbl> <dbl> <dbl> <dbl>
#> 1 data/01-sales.csv January  2019     1  1234     3
#> 2 data/01-sales.csv January  2019     1  8721     9
#> 3 data/01-sales.csv January  2019     1  1822     2
#> 4 data/01-sales.csv January  2019     2  3333     1
#> 5 data/01-sales.csv January  2019     2  2156     9
#> 6 data/01-sales.csv January  2019     2  3987     6
#> # ℹ 13 more rows

Encore une fois, le code ci-dessus fonctionnera si vous avez les fichiers CSV dans un dossier data de votre projet. Vous pouvez télécharger ces fichiers depuis https://pos.it/r4ds-01-sales, https://pos.it/r4ds-02-sales, et https://pos.it/r4ds-03-sales ou vous pouvez les importer directement avec :

sales_files <- c(
  "https://pos.it/r4ds-01-sales",
  "https://pos.it/r4ds-02-sales",
  "https://pos.it/r4ds-03-sales"
)
read_csv(sales_files, id = "file")

L’argument id ajoute une nouvelle colonne appelée file au data frame résultant qui identifie le fichier d’où proviennent les données. C’est particulièrement utile dans les cas où les fichiers que vous lisez n’ont pas de colonne d’identification qui puisse vous aider à retracer les observations jusqu’à leurs sources d’origine.

Si vous avez de nombreux fichiers à importer, ça peut être long de les lister un à un. Vous pouvez alors utiliser la fonction list.files() pour trouver les fichiers avec une caractéristique commune (pattern) dans les noms de fichiers. Vous en apprendrez plus sur ces patterns dans le Chapitre 15.

sales_files <- list.files("data", pattern = "sales\\.csv$", full.names = TRUE)
sales_files
#> [1] "data/01-sales.csv" "data/02-sales.csv" "data/03-sales.csv"

7.5 Exporter un fichier

readr propose aussi deux fonctions utiles pour écrire / exporter les données sur le disque : write_csv() et write_tsv(). Les arguments les plus importants de ces fonctions sont x (le data frame à exporter) et file (l’endroit où il sera enregistré). Vous pouvez aussi spécifier comment les valeurs manquantes sont écrites avec na, et si vous voulez ajouter des données à la fin d’un fichier existant (avec append).

write_csv(students, "students.csv")

Maintenant, relisons ce fichier csv. Notez que les informations du type de variable que vous veniez de configurer sont perdues quand vous exportez au format CSV, car vous lisez les données à partir d’un fichier texte brut :

Cela rend les CSV peu fiables pour sauvegarder des résultats intermédiaires — vous devez spécifier le typage des colonnes chaque fois que vous chargez les données. Il y a deux principales alternatives :

  1. write_rds() et read_rds() sont des wrappers standards des fonctions de base readRDS() et saveRDS(). Elles stockent les données dans le format binaire personnalisé de R appelé RDS. Cela signifie que quand vous rechargez l’objet, vous chargez exactement le même objet R que vous venez d’exporter.

    write_rds(students, "students.rds")
read_rds("students.rds")
#> # A tibble: 6 × 5
#>   student_id full_name        favourite_food     meal_plan             age
#>        <dbl> <chr>            <chr>              <fct>               <dbl>
#> 1          1 Sunil Huffmann   Strawberry yoghurt Lunch only              4
#> 2          2 Barclay Lynn     French fries       Lunch only              5
#> 3          3 Jayendra Lyne    <NA>               Breakfast and lunch     7
#> 4          4 Leon Rossini     Anchovies          Lunch only             NA
#> 5          5 Chidiegwu Dunkel Pizza              Breakfast and lunch     5
#> 6          6 Güvenç Attila    Ice cream          Lunch only              6

  2. Le package arrow vous permet de lire et d’écrire des fichiers parquet, un format de fichier binaire rapide qui peut être partagé entre les langages de programmation. Nous reviendrons à arrow plus en détail dans le Chapitre 22.

    library(arrow)
write_parquet(students, "students.parquet")
read_parquet("students.parquet")
#> # A tibble: 6 × 5
#>   student_id full_name        favourite_food     meal_plan             age
#>        <dbl> <chr>            <chr>              <fct>               <dbl>
#> 1          1 Sunil Huffmann   Strawberry yoghurt Lunch only              4
#> 2          2 Barclay Lynn     French fries       Lunch only              5
#> 3          3 Jayendra Lyne    NA                 Breakfast and lunch     7

#> 5          5 Chidiegwu Dunkel Pizza              Breakfast and lunch     5
#> 6          6 Güvenç Attila    Ice cream          Lunch only              6

Parquet est beaucoup plus rapide que RDS et est utilisable en dehors de R, mais nécessite le package arrow.

7.6 Saisie de données

Parfois, vous aurez besoin d’assembler un tibble « manuellement » en faisant un peu de saisie de données dans votre script R. Il y a deux fonctions utiles pour vous aider à le faire, qui diffèrent selon la manière dont vous spécifiez votre tibble, par colonnes ou par lignes. tibble() fonctionne par colonne :

tibble(
  x = c(1, 2, 5), 
  y = c("h", "m", "g"),
  z = c(0.08, 0.83, 0.60)
)
#> # A tibble: 3 × 3
#>       x y         z
#>   <dbl> <chr> <dbl>
#> 1     1 h      0.08
#> 2     2 m      0.83
#> 3     5 g      0.6

La disposition par colonne complique la comparaison des lignes, donc une alternative est tribble(), abréviation de transposed tibble (tibble transposé), qui vous permet de disposer vos données ligne par ligne. tribble() est personnalisée pour la saisie de données dans le code : les en-têtes de colonnes commencent par ~ et les entrées sont séparées par des virgules. Cela permet de présenter de petites quantités de données sous une forme facile à lire :

tribble(
  ~x, ~y, ~z,
  1, "h", 0.08,
  2, "m", 0.83,
  5, "g", 0.60
)
#> # A tibble: 3 × 3
#>       x y         z
#>   <dbl> <chr> <dbl>
#> 1     1 h      0.08
#> 2     2 m      0.83
#> 3     5 g      0.6
